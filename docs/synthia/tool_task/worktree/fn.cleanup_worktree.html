Clean up a worktree after a sub-agent finishes.

Algorithm (mirrors cleanupWorktree in pi-subagents/src/worktree.ts):

  1. git status --porcelain — empty ⇒ clean tree.
  2. Clean tree, HEAD == base_sha ⇒ remove the worktree silently (no changes, nothing to keep).
  3. Clean tree, HEAD diverged from base_sha ⇒ the agent made committed changes without leaving uncommitted ones (rare; happens if the agent committed itself). Treat as “has changes” and branch from current HEAD.
  4. Dirty tree ⇒ git add -A + git commit -m '…' then git branch <branch>. The branch is created in the base repo because the worktree’s detached HEAD would not otherwise persist. After the branch lands, the worktree is removed so the temp dir does not leak.

description is the agent description (truncated to 200 chars) — it ends up in the commit message so the user can tell which sub-agent produced the branch.
