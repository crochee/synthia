synthia::session

Module manager 

Source
Expand description

In-memory registry that owns SessionSink instances.

After the panel/session refactor each session is identified by (user_id, session_id) and persisted through a SessionSink rooted at <sessions_root>/<user_id>/<session_id>/. The registry:

  1. Eagerly creates the sink when a session is created, so the on-disk directory exists before the controller starts appending events.
  2. Hands out the same Arc<dyn SessionSink> for repeated lookups of the same session (cheap clones).
  3. Provides a shared InputQueue for the controller’s “prompt / steer” command channel.

SessionRegistry is intentionally minimal: it does NOT store state machines, budgets, approvals, or any policy concerns. Those live in synthia-server::session::SessionController.
