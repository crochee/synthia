Snapshot + op-log persistence for SearchEngine.

Layout under root:

  • snapshot.json — the full alive set ({ item, vector } per doc), written atomically (.tmp + rename) by SearchEngine::save and by the compact hook.
  • ops.jsonl — append-only add / remove records since the last snapshot; one JSON object per line.

SearchEngine::load = snapshot + op replay. Vectors are persisted, so non-deterministic embedders (e.g. provider-backed) restore without re-embedding; BM25 postings are rebuilt from Searchable::indexed_fields (deterministic, cheap) and never hit disk.

The methods live on a dedicated impl block gated on T: Serialize + DeserializeOwned: a SearchEngine<T> over a non-serde T simply has no save / load.
