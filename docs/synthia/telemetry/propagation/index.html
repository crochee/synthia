W3C TraceContext propagation helpers built on the official OpenTelemetry propagator.

The HTTP-level traceparent / tracestate parsing and formatting is delegated to [opentelemetry_sdk::propagation::TraceContextPropagator], the reference implementation of W3C TraceContext Level 1. We do not hand-roll the format anywhere — that crate is the canonical industry-standard implementation and matches the OTel SDK’s runtime behavior byte-for-byte.

§Two layers

  • The global-propagator install (register_global_propagator): installs the standard propagator into opentelemetry::global::set_text_map_propagator so any code that asks for the global propagator (including the OTel SDK tracer layer) receives the same W3C implementation. It is crate-private; the two shims below install it lazily on first use.
  • extract_trace_context / inject_trace_context: thin shims that take an [Extractor] / [Injector] adapter (typically an axum HeaderMap adapter built in the consumer crate) and delegate to the registered propagator. The telemetry crate stays free of HTTP-layer dependencies.

§synthia-server middleware

crates/synthia-server/src/middleware/trace_context.rs is an axum::middleware::from_fn that builds a HeaderMap adapter here and calls these helpers. It does not parse or format traceparent itself.
