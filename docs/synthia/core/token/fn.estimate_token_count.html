pub fn estimate_token_count(text: &str) -> usize
Expand description

Approximate token count for text.

Uses a coarse heuristic (4 ASCII bytes per token, 1.5 CJK characters per token) plus a 5% overhead. Provider-native BPE tokenizers should be preferred when accuracy matters — this helper exists for pre-flight budget checks only.

ASCII fast path: str::is_ascii (SIMD) answers “is there any multi-byte character at all?” in one pass, and for pure-ASCII text every character is one byte and none is CJK — so the byte length is ascii_count and the per-character decode plus the twelve is_cjk range checks can be skipped entirely. Prompt text is overwhelmingly ASCII, and this function runs per message on the compaction path (see the hot_paths benchmark). Non-ASCII input takes the original loop, byte for byte.
