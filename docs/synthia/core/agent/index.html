AgentDescriptor / AgentFilter — the cross-cutting agent identity types.

These types used to live in synthia-harness. They moved here because every cross-crate surface (registry filters, delegation peers, server route bodies, evaluation harnesses) needs the static identity metadata of an agent without pulling the agent runtime in. Putting them at the foundation of the dependency graph lets the consumer-facing crates talk about an agent’s identity without a transitive synthia-harness dependency.

§What lives here

  • AgentDescriptor — the industry-aligned identity + capability metadata (Anthropic Agent SDK / OpenAI Swarm / MCP reference designs).
  • AgentFilter — the conjunctive filter shape used by Registry::list_paginate for agents.

§What deliberately stays in synthia-harness

  • AgentEntry (descriptor + boxed runtime Agent) — it owns an Arc<dyn Agent> and therefore a hard synthia-harness dependency.

§Identity (industry-aligned)

  • name / description — identity (Anthropic name, OpenAI name + handoffDescription).
  • kind / version — paradigm + schema revision.
  • instructions — the system prompt (Anthropic instructions, OpenAI instructions).
  • model_hint — preferred model identifier (Anthropic model, OpenAI model).
  • tools — tool names exposed directly (OpenAI tools).
  • capabilities — coarse capability tags (“streaming”, “cancellation”, …); finer-grained than tools.
  • handoffs — agent names this specialist can route to (OpenAI handoffs).
  • handoff_hint — short label describing when an orchestrator should route to this agent (OpenAI handoffDescription).
  • output_schema — optional JSON-schema reference for structured outputs (OpenAI outputType).
  • owner / domain — ownership + functional domain, useful for multi-tenant routing.
  • persona — short role-framing sentence surfaced verbatim to the LLM (e.g. "You are a strict security reviewer"). Distinct from the long-form instructions.
