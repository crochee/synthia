## Wave 1 — file-disjoint, parallel

- **M. File-backed scoped long-term memory** (`synthia-context`, pi-subagents §memory) — `FileMemory: Memory` with `user` / `project` / `local` scopes, a bounded `MEMORY.md` index (≤200 lines) plus frontmatter entry files, deterministic keyword recall (descending score, id tie-break), ULID entry ids, read-only mode, and path defenses (name whitelist, symlink + traversal refusal). Completes the 3-layer memory design whose long-term tier is currently documented as "process (until a persistent backend exists)".
- **N. OS-level execution policy** (`synthia-tool` + one `synthia-session` event, dsh §sandbox) — `ExecutionPolicy { ReadOnly, WorkspaceWrite, DangerFullAccess }`; `SandboxBackend::confine(policy, workspace_root) -> ConfinedCommand` returning **the argv to spawn instead** (so the sandbox is argv construction, not a wrapper process); `BwrapBackend` builds bubblewrap argv (ro-bind `/`, bind the workspace, pid/net unshare per policy, `--die-with-parent`); availability is probed once and **fail-closed** — a confinement policy with no usable backend refuses to run rather than running unconfined, while `DangerFullAccess` bypasses explicitly; `effective_policy(grants, events, default)` is a pure fold (explicit grant > session override > deployment default) over a new `SessionEvent::SandboxMode`; denial dialects ("read-only file system" / "permission denied" / "operation not permitted") are classified so the model can tell policy denial from command failure; `policy_prompt_block` tells the model its write scope.
- **O. Two-pool subagent concurrency + invocation records** (`synthia-agent`, pi-subagents §agent-manager) — `SubagentPool` as a pure admission state machine: background lane bounded (default 10) with a FIFO queue, foreground unbounded, nested children occupy no slot (the deadlock guard), tombstones keep the last 100 finished children addressable, and `InvocationRecord` captures requested-vs-effective model/tier + usage + depth + status. No threads/timers — the caller drives admission and release.
- **W. Declarative workflow runtime + journal** (new crate `synthia-workflow`, pi-subagents §workflow) — the JS script VM is replaced by a serde `WorkflowSpec` (agent / fan-out / pipeline steps) executed by `WorkflowRuntime` through a single `WorkflowHost` effect seam (`spawn_agent` / `run_gate`) so caps, concurrency and abort are enforceable and tests inject a fake host. Caps default to agents 1000 / items 4096 / nested 256; concurrency defaults to `min(16, cpus-2)` with drain-on-abort; `WorkflowJournal` is JSONL keyed by sha256 of each call's identity fields, tolerates a torn last line, replays the longest matching prefix and re-runs the tail (a failed recorded step re-runs, never replays as failure); `WorkflowControl` is a typed pause/resume/skip/retry/abort state machine.

## Wave 2 — after wave 1 (shared files)

- **P. Named tool groups** (`synthia-tool`, traitclaw §registries) — `GroupedRegistry` read-side wrapper: `visible_tools()` returns active groups only (what the model is offered), `find(name)` searches **all** groups (a deactivated tool stays executable). The visibility ≠ executability split is the point.
- **Q. Progressive example ladder** (`crates/*/examples/**` + `docs/examples/README.md`, traitclaw §examples) — 8–12 minimal one-seam examples (tool groups, derive-tool, eval suite, replay provider, run-inbox steering, runtime context, delegation gate, worktree isolation, token meter, sandbox policy, workflow fan-out), each runnable with no network and indexed in the new docs README. Doubles as executable documentation for the "use synthia as a library" story.
