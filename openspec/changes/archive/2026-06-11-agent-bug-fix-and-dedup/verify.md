### 3.2 Partial unification of `LoopDetectorSet` (warning, not failure)

The original plan's verification 5.6 expected `grep -r "pub struct LoopDetector" crates/` to return 1 result, but it returns **2** — both `LoopDetectorSet`:

| Location | Detectors (fields) | API |
|---|---|---|
| `crates/synthia-guardian/src/loop_detector.rs:254` | `generic_repeat, poll_no_progress, ping_pong, global_circuit, last_result` | `check_tool_call(&str, &str)`, `record_tool_call(...)`, `last_detection()` |
| `crates/synthia-agent/src/stream_builder/loop_detection.rs:280` | `generic_repeat, no_progress, global_circuit, doom_loop` | Uses `(u64, u64)` hash API, returns `LoopStatus` |

**Why both remain**:
- The original `agent::LoopDetector` (the 3rd duplicate) was dead code and was deleted cleanly (DEAD-CODE-3.8-3.21).
- The `stream_builder::LoopDetectorSet` is **actively used** by `AgentDependencies` and `stream_builder::builder` — it cannot be removed.
- The two implementations have **different detector sets** (`ping_pong` vs `doom_loop`; `poll_no_progress` vs `no_progress`) and **different APIs** (string-based vs hash-based). Unifying them is non-trivial and requires deciding:
  1. Which detector set is canonical?
  2. Which API style is canonical (string args or hash)?
  3. Migration of all callers.

**Decision**: defer to **Phase 3** (re-evaluation 2026-12-10). Documented in CHANGELOG "Deferred" section.
