# Brainstorm: Synthia Agent 生产就绪

## 背景

synthia-agent 是一个基于 Rust 的 AI agent 框架，实现 ReAct 模式。当前就绪度约 55%，需要达到"稳定可靠"标准，作为日常编码和生活助手使用。

## 需求决议链

### Q1: 使用场景？
**决议**: 编码助手 + 生活助手（两者兼顾）

### Q2: 部署方式？
**决议**: 本地 CLI — 直接运行在开发机上，零延迟、文件系统直接访问

### Q3: LLM 提供商配置？
**决议**: 模型路由 — 根据任务复杂度自动选择模型（简单任务便宜模型，复杂推理用强模型）

### Q4: 核心能力？
**决议**: 定时/周期任务 — 提醒、定时报告、定时信息检索

### Q5: 定时任务执行模式？
**决议**: 混合模式 — 简单任务独立执行，复杂任务注入当前会话

### Q6: 记忆策略？
**决议**: 文件系统 (P10) — Phase 0 用文件系统，不用向量数据库

### Q7: 可靠性期望？
**决议**: 稳定可靠 — 不丢数据、不无限阻塞、错误可恢复、超时可控、有可观测性

## 当前架构成熟度

| 模块 | 就绪度 | 关键缺口 |
|------|--------|----------|
| 核心引擎 | 80% | 健康检查缺失 |
| 工具系统 | 50% | 无超时控制、Subagent 不等待、Cron 工具缺失 |
| 上下文管理 | 60% | 修剪粗暴、无渐进降级、无 KV Cache 追踪 |
| 记忆系统 | 50% | 无 memory_search、无事件日志、无注入策略 |
| 可观测性 | 40% | 有 Prometheus 端口但缺关键指标 |
| 定时任务 | 50% | 时间轮+Cron 解析器已有，缺桥接层和持久化 |

## 方案对比

### 方案 A: MVP（最小可行）
修复核心缺陷，让它"稳定能用"。不做渐进降级、不做记忆检索。
**排除原因**: 达不到"稳定可靠"标准

### 方案 B: 稳定可靠版（推荐）
补齐所有关键路径的可靠性，不丢数据、可控超时、错误可恢复。
**选择原因**: 正好匹配需求，不过度也不不足

### 方案 C: 完整生产版
企业级 SLA、混沌测试、向量记忆。
**排除原因**: 本地 CLI 不需要

## 设计取捨

1. **KV Cache 前缀一致性** — 最高优先级，所有其他设计服从它
2. **文件系统优先记忆** — 简单、透明、可审计，Phase 1 再加向量搜索
3. **Append-Only 上下文** — 只追加到末尾，不插入不重排
4. **不信任 LLM** — 防护机制独立于 LLM，基于规则和 hash
5. **渐进降级** — 能在 Stage 1 解决的不升级到 Stage 2

## 风险

- 事件日志敏感数据脱敏（P0）
- Shell 命令黑名单绕过（P1）
- 后台任务安全约束（P0）
- 错误恢复死锁循环（P1）
- 现有 11 个编译错误（前置任务）
